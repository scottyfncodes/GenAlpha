# Character art — production candidates

**Status: QA candidates only. Nothing here is approved production art, and
nothing here has been copied to `public/art/`.**

This directory holds output from the production method chosen in
`docs/art/genalpha-character-art-production-decision.md` (procedural,
vector-free pixel construction) — parallel to `docs/art/rnd/`'s existing
"reference/exploration only" convention, but one stage further along: a
candidate here has already passed the automated discrete-pixel-data gate
and is waiting on the production brief's §14–16 human/gameplay-scale
review before it can be promoted.

## `character.player.candidate1.png`

Generated by `scripts/generate-character-production.mjs` (pure pixel-buffer
construction — no `<canvas>`, no image-generation model, no continuous-tone
step anywhere in the pipeline). Iteration 2 folded in style cues from a
user-supplied reference image (an outline stroke, a bumpier/curlier hair
silhouette, a two-tone shoe, a drawstring seam) — that reference was
measured first, the same way the two rejected submissions were: ~38.5%
partial-alpha pixels, ~50,000 unique colors, non-integer 3×4 cell
dimensions. Same failure as before, just styled more convincingly. It's
used here as language reference only, same as Direction A's own R&D images.

Verified against every automated gate in `scripts/check-character-art-quality.mjs`:

```
[PASS] Dimensions                                        48x88 -> cell 16x22 (expected aspect 16:22 = 0.7273, got 0.7273)
[PASS] Grid/cell count                                   3x4 = 12 cells (manifest expects 12: 3 frames x 4 directions)
[PASS] Transparency behavior                             every pixel is alpha 0 or 255; every cell has both transparent and opaque pixels
[PASS] Unique color count                                10 unique opaque colors (ceiling: 24)
[PASS] Color-run characteristics                         median horizontal same-color run length: 2px (floor: 2px, n=1601 runs)
[PASS] Palette consistency                               0 of 12 cells contain a color no other cell uses (0-1 expected; skin/hair-only cells can legitimately be unique)
[PASS] Anchor consistency                                lowest-opaque-pixel row varies by 0px across cells (expect 0) and sits at row 21 of 22 (expect the last row, 21 — on the anchor edge); idle-column horizontal centroid within 1px of center (cell center x=7.5)
[PASS] Accidental anti-aliasing / near-duplicate colors  no two palette colors within 24 RGB distance of each other
[PASS] Direction completeness                            all non-mirror direction pairs distinct; left/right mirror diff 0px (tolerance 35px) — within tolerance

All gates passed.
```

This is the proof-of-viability the decision document's §7 next-step called
for: the chosen method can produce a full 3×4 sheet that is genuinely
discrete pixel data by construction (10 unique opaque colors, binary alpha,
multi-pixel color runs), not the ~87,000–93,000-color (or ~50,000-color)
continuous-tone output the rejected submissions and reference produced.

**Hoodie color:** black, per request — pure black for the main body (reused
from the `shoe` color already in the palette, not a new hex), with the
existing `world/draw.ts` `PALETTE.copUniform` navy as the hem/accent step.
A pure-navy main fill was tried first but sat only ~21 RGB-distance from
`PALETTE.ground`, and the torso visibly thinned into the background in a
gameplay-scale render — demoting it to the accent step fixed that while
keeping the two-tone read.

**A bug the anchor gate initially missed, fixed in the same pass:** the
first iteration's leg shape used an exclusive upper bound that never
actually reached the cell's last row, floating the feet 1px above the true
anchor edge — every cell agreed on the same (wrong) lowest row, so a
consistency-only check passed anyway. The gate now also asserts the lowest
opaque row equals the cell's actual last row, not just that all cells agree
with each other.

**What this candidate is not, yet:**

- Not judged against the production brief's §14 pass/fail bar (silhouette
  read at native size, walk-cycle-as-motion, "reads as a kid/the
  protagonist within a second") — that's a human call, deliberately not
  something the automated gate checks.
- Not judged at gameplay scale (§16) — in context, 2×, next to
  `public/art/prop.tree.tall.png`/`vehicle.car.png` on the real
  `PALETTE.ground` fill.
- Not wired into `public/art/character.player.png` — promotion is a
  separate, explicit step after the above review, per the decision
  document's §5 proposed pipeline. `world/draw.ts`, the manifest, and
  every existing file under `public/art/` remain untouched by this
  candidate's existence.
